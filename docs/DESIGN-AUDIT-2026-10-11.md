# 디자인·레이아웃 수정 검증 — 2026-10-11

기존 변경을 유지한 상태에서 실제 OxiMemo 앱을 사용해 확인한 문제를 수정했다.
수정 전 작업 트리 576개 파일의 SHA-256, 파일 복사본과 기존 Git 패치를
`/tmp/oximemo-design-fixes-baseline/`에 보존했다. 개인 볼트는 검증 대상으로
사용하지 않고 별도 테스트 볼트에서 새 빌드를 확인했다. 감사 검증 단계에서는
기존 설치 앱을 교체하지 않았다.

| P3 | Copilot이 켜져도 연결되지 않은 이유가 안 보임 | 에이전트 미설정 상태와 감지 동작 안내 |
| P3 | 컬렉션 접기 화살표 방향이 반대 | 펼침 상태와 화살표 방향 일치 |

메모 대화상자의 접근성 이름도 ‘완료’에서 실제 메모 제목으로 수정했다.
자동 저장과 완료 버튼의 저장은 직렬화했고, 원본 해시 충돌 시 입력을 창에
보존하며 반복 자동 저장을 중단한다. 제목 변경·위키링크 갱신·폴더 삭제와
복구를 새 형식에서도 유지한다. PDC 이전 계획 전체의 완료를 뜻하지 않는다.
충돌 뒤에는 ‘저장되지 않음’을 표시하며, 초안을 복사한 다음 원본을 다시
불러오는 동작으로 편집기를 새 원본에 맞춰 갱신한다.

## 컴퓨터 유즈 재검증

새 네이티브 앱과 별도 테스트 볼트에서 확인했다.

- 1100×720 및 960×526 창: 경로와 보기 메뉴가 보이고, 그래프의 노드 3개와 연결선이 표시된다.
- 검색 결과 없음 → 필터 모두 지우기: 검색어가 비고 원래 메모 목록이 복원된다.
- 작은 창의 데일리 메모: 속성 3개가 기본 접힘 상태이고 본문 제목이 바로 보인다.
- 할 일 ‘오늘’ 보기: 조건에 맞는 항목이 없다는 안내와 추가 버튼이 보이며, 버튼이 입력창을 연다.
- 캡처: 실행 방법이 먼저 보이고 반응 속도·높이를 펼쳐 조절할 수 있다.
- Copilot: 활성화되어 있지만 선택한 에이전트가 없는 이유와 탐지 버튼이 보인다.
- 컬렉션: 펼침 상태와 화살표 방향이 일치하며 내용이 나타난다.
- 새 Markdown·HTML 작성 → 저장 → 다시 열기: 본문이 유지되고, 카드·리스트에서 제목과 같은 첫 본문 제목이 반복되지 않는다.
- 제목 기반 위키링크 클릭: 대상 메모 ‘레이아웃 점검 A’가 열리며 해당 본문이 보인다.
- 외부 변경 → 다른 로컬 초안 입력 → 완료: 충돌 안내와 초안이 남고 ‘저장되지 않음’이 표시된다. 복사 후 다시 불러오기에서는 외부 변경이 포함된 원본이 나타나며 파일 해시가 바뀌지 않는다.
- PDC 문서 목록: 새 Markdown·HTML·데일리는 PDC 문서, 기존 미표시 Markdown과 템플릿은 일반 Markdown으로 보인다. 마지막 빌드에서 파일 9개의 검사 결과는 ‘발견된 문제 없음’이다.
- 검증 볼트의 초기 파일 11개는 읽기·탐색 후 SHA-256이 모두 동일하다. 수정하지 않은 기존 작업 및 코퍼스 파일 200개도 작업 전 복사본과 바이트가 동일하다.

재검증에서 제목 기반 위키링크도 확인했다. UUID와 제목·별칭을 구분해 해석하고, 같은 이름이 여러 개면 임의의 메모를 선택하지 않는다.
PDC 검사 화면도 경로 해석 이후 표시 제목을 확인해, 편집기에서 열리는
제목 링크를 끊어진 링크로 오인하지 않게 했다. 동명의 제목은 진단으로
남기며, 링크 원문과 문서 ID는 바꾸지 않는다.

이 과정에서 macOS의 `/tmp`와 `/private/tmp` 경로 별칭 때문에 워처가 새
메모 위치를 빈 문자열로 기록하는 문제도 재현했다. 경로 해석과 인덱스
재구성을 수정하고 원본을 다시 쓰지 않고 테스트 인덱스를 복구했다.
최종 빌드에서 메모 작성·재열기와 PDC 분류, 외부 변경 충돌 복구까지 확인했다.
