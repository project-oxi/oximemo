# 모바일 메모 UX 설계와 검증

작성일: 2026-10-21. 범위: 모바일 전체 이용 흐름, PC 기능 격차, 작성 경험.
이 문서는 구현된 기능과 후속 설계를 구분한다. PC와 기능이 동등하다는 선언이 아니다.

## 제품 역할과 근거

사용자는 같은 보관함을 PC와 휴대폰에서 이어서 사용한다. 모바일의 핵심 작업은
떠오른 생각 기록, 기존 메모 검색, 긴 글 읽기, 작은 수정, PC로 전송이다.
`README.md`, `DESIGN.md`, `docs/MOBILE.md`, 모바일 App/NoteEditor/Connection,
PC MemoDetail/Sidebar/TasksView/GalleryView, `oximemo-sync::Change`를 기준으로
비교했다. 외부 경쟁 앱 조사는 수행하지 않았다. 사용자 인터뷰나 사용 시간 측정 결과는 없다.

PC의 모든 화면을 축소하기보다 같은 문서를 다루는 핵심 작업의 완결성을 우선한다.
그렇다고 모바일에서 읽기만 가능하거나 모든 정리를 PC에 의존하는 상태를 최종 제품으로
보지 않는다. 작성 안전성 → 정리 → 첨부와 연결 → 고급 보기 순서로 기능을 확장한다.

## 정보 구조

- **메모:** 기본 진입점. 전체 메모, 전송 대기, 폴더 필터. 검색과 새 메모는 상단 고정.
  필터를 바꾸거나 상세 화면에서 돌아와도 검색어와 목록 위치를 유지한다.
- **읽기:** 본문이 중심. 상단에 뒤로, 저장 상태, 편집. 파일 경로와 원문은 문서 정보에 둔다.
  미지원 문서는 원문과 진단을 제공하며 빈 화면으로 숨기지 않는다.
- **작성:** 제목 → 본문 → 미리보기 → 저장. 제목 입력은 선택 사항. 제목의 Return은
  본문으로 이동한다. 저장은 기기 보관, 동기화는 별도 결과로 설명한다.
- **설정:** PC 연결, 전송 대기, 휴지통, 화면 모드, 저장 안내.
- **PC 연결:** 연결 상태와 마지막 동기화, 재시도. QR 스캔이 주 동작이고 코드/주소 입력은 대안.

현재 목적지 수로는 하단 탭을 추가하지 않는다. 작성 도구는 작성할 때만 나타난다.
향후 보관함이 폴더·태그·즐겨찾기까지 다루면 별도 보관함 화면을 추가하고, 검색은
메모 화면에서 바로 시작하도록 유지한다.

## 이번 작성 도구의 세부 규칙

본문 도구는 최소 44px 터치 영역을 가진다. 체크리스트를 앞에 배치하고, 좁은
화면에서 서식 영역만 가로로 스크롤한다. Undo/Redo는 고정한다. 버튼을 누를 때
본문 선택을 잃거나 키보드를 불필요하게 닫지 않는다. 키보드로도 접근할 수 있다.

굵게/기울임은 선택 범위에 감싸기를 적용하고 같은 선택에서 다시 누르면 해제한다.
줄 서식은 선택된 물리적 줄에만 적용한다. 선택이 다음 줄 시작에서 끝나면 그 줄은
포함하지 않는다. Return 자동 처리는 일반 목록/체크리스트/번호 목록만 대상으로 하며,
코드 fence 안, 사용자 확장 체크 상태, IME 조합 중, Shift+Return에는 개입하지 않는다.

Undo/Redo는 본문 편집에 한정하고 버튼 이름도 이를 명시한다. 제목 편집은 시스템
텍스트 입력 동작을 유지한다. 본문 이력은 편집 세션의 메모리 데이터이며 최대 80개,
누적 문자열 8MiB 기준으로 오래된 항목을 정리한다(현재/직전 2개는 보존).
복구 초안이나 영구 문서 버전 관리로 표현하지 않는다.

원문은 textarea 표시값과 분리한다. CRLF/혼합 개행은 표시할 때 LF로 보이더라도
변경 구간 밖의 원문 terminator를 보존한다. 원문/미리보기 전환은 저장을 발생시키지 않는다.
PDC Stage 2의 원문 보존·안전한 미리보기 게이트를 먼저 보강하는 변경이다.

## 후속 기능의 완료 조건

1. **복구 초안:** 타이핑 중 앱 종료 → 재실행 → 복구 배너 → 같은 제목/본문/커서 복원.
   원본이 바뀌면 최신 digest로 재지정하지 않고 충돌 또는 새 메모 보관을 제시한다.
   앱 전환 때 복구본을 내구성 있게 저장하며 실패를 숨기지 않는다.
2. **정리:** 기기에서 태그/즐겨찾기/폴더를 바꿈 → 오프라인 표시 → PC 재연결 → 같은 ID 유지.
   미지원 서버에는 조작을 비활성화하고 이유를 제공한다. 알 수 없는 envelope 필드 보존.
3. **첨부:** 오프라인 사진 삽입 → 앱 재시작 → 미리보기 유지 → PC 업로드 → digest 검증.
   실패하면 본문/자산을 함께 보관하고 재시도한다. 원격 이미지 자동 fetch 금지.
4. **삭제/복원:** 전송 재시도에도 중복 작업이 없고, tombstone은 발견 가능 경로에 유지한다.
   PC와 충돌하면 사용자 확인 없이 삭제하거나 복원하지 않는다.
5. **링크:** 같은 제목의 메모, 이동한 메모, 없는 대상, vault 밖 경로를 각각 검증한다.

## 검증 기록

자동화 테스트와 브라우저 QA는 샘플 캐시를 사용하며 실제 사용자 보관함을 수정하지 않는다.
실제 단말의 한글 키보드, 받아쓰기, 키보드 액세서리 터치, OS 종료/재실행, 실제 PC 왕복은
별도 실기기 게이트다. 브라우저 화면 높이 축소가 실제 키보드 검증을 대체하지 않는다.

실행 결과는 이 문서 말미에 기록한다.

## 마크다운 읽기 경험

동일한 렌더러를 미리보기와 저장 후 읽기에 사용한다. 본문과 동일한 선두 H1만
읽기 화면에서 생략하며, 들여쓴 코드의 `#` 또는 다른 제목은 숨기지 않는다.

- 문단, 제목, 중첩 목록은 글자 확대에 따라 자연스럽게 줄바꿈한다. 한국어는
  어절 단위 줄바꿈을 우선하고 긴 연속 문자열만 강제로 나눈다.
- 체크리스트는 글머리표를 중복 표시하지 않고 완료 여부를 명확히 구별한다.
  미리보기 checkbox는 PDC render policy에 따라 비활성이다.
- GFM 표는 좌/중앙/우 정렬을 보존한다. 표만 가로로 스크롤하고 키보드로도 접근한다.
- 코드 블록은 언어 라벨과 실제 동작하는 복사 버튼을 제공한다. 긴 줄은 코드 안에서
  스크롤한다. 복사 거절/미지원이면 실패를 알리고 텍스트 선택을 안내한다.
- `==강조==`와 `[!tip]` 등 콜아웃은 파서 토큰 단계에서 표현한다. 코드 속 문법은
  해석하지 않으며, 알 수 없는 callout 이름도 텍스트로 남긴다.
- 링크·첨부는 대상 문자열을 원문 그대로 보존하고, 명시적으로 누르면 호스트에서
  처리한다. 수식/각주 전용 렌더링은 미구현이다. 후속 구현은 아래에 정리했다.
  이 제한을 숨겨 전체 Markdown/Obsidian 동등성으로 표현하지 않는다.
- raw HTML은 텍스트로 유지하고, 코드·콜아웃·강조를 포함한 전체 결과를 sanitize한다.
  preview DOM을 다시 저장 원문으로 직렬화하지 않는다.

검증용 `qa/markdown-fixture.ts`는 제목, 목록, 체크리스트, 콜아웃, 강조, 표, 긴 코드,
참조와 첨부를 한 문서에 담는다. production entry에서는 이 fixture를 불러오지 않는다.

## 첨부·링크·재실행 복구 후속 구현

- 미저장 제목·본문·원래 문서 스냅샷을 WKWebView의 앱 전용 persistent storage에
  보관한다. PC 전송 대기열과 별도이며, 복구 자체로 저장/전송하지 않는다.
  저장/명시적 버림/편집 되돌리기 완료 시 복구 사본을 제거한다. 저장 공간 부족은
  사용자에게 표시한다. iOS suspension 전 동기식 storage write를 사용한다.
- native save는 편집 시작 시 source/pending 스냅샷과 현재 cache를 비교한다.
  달라졌으면 원문을 덮어쓰지 않고 새 메모로 보관할 수 있다.
- 복구 시 목록에서 편집기로 가는 history entry를 재구성한다. 첫 시뮬레이터
  테스트가 발견한 복구 후 back 버튼 무동작을 수정했다. 링크 이동에도 미저장
  내용의 저장/버림/계속 작성 guard를 적용한다.
- 링크는 눌렀을 때만 처리한다. 상대 문서 경로·UUID·유일한 wiki 경로는 로컬
  목록에서 찾고, HTTP(S)는 native opener로 외부 브라우저에서 연다.
  모호하거나 누락된 링크는 오류가 보인다. heading/block fragment 이동은 아직
  구현하지 않았다.
- PC `/v1/attachment`와 native transport를 추가했다. 문서 상대 경로 또는 PDC
  SHA-256 asset만 읽고, vault 탈출·symlink·private 경로를 거부한다. digest
  asset은 server와 client에서 검증한다. 현재 모바일 전송 상한은 8 MiB다.
  이미지 버튼은 사용자가 누르면 가져오며 PNG/JPEG/GIF/WebP signature만 이미지로
  표시한다. 기타 파일은 파일명/크기를 표시한다. PDF/문서 전용 viewer와 오프라인
  attachment cache는 아직 없다. 외부 이미지 URL은 자동 다운로드하지 않는다.
- 목록 발췌는 문단 줄바꿈, 체크 상태, wiki 표시명, 표의 읽을 수 있는 텍스트를
  유지한다. 댓글·서식 기호는 발췌에서 제거하며 원문은 그대로 둔다. 접근성 설명도
  240자로 제한해 긴 본문 전체를 각 행에서 반복하지 않는다.
