# 설계 리뷰: Finder형 탐색 UX 재설계

> **날짜:** 2026-08-20
> **대상:** `2026-08-20-finder-navigation-design.md`
> **성격:** 코드 대조 기반 설계 검증 + 개선 설계. 구현 없음.
> **판정:** 구조는 채택. 단 **차단급 결함 4건**을 고치기 전에는 구현 착수 불가. 원본 §2 결정 중 3·5·7·9와 §3.1·§4.2·§5.1·§6.3·§10은 이 문서로 대체된다.

## 0. 총평

**옳은 것:** 3면 구조(사이드바=큐레이션 / 메인=위치의 내용물 / 브레드크럼=위치의 단일 진실)와 브라우즈·쿼리 2모드 분리는 정확한 진단이다. `folderFilter` 타입을 유지하고 해석만 바꾸는 접근도 마이그레이션 비용 대비 이득이 크다. 이 골격은 유지한다.

**틀린 것:** 원본은 **현재 코드의 실태를 두 곳에서 잘못 읽었다.**

1. "폴더로 이동…"이 동작한다고 가정했지만 **무동작 + 거짓 성공 토스트**다. → DnD(P3)가 그 위에 쌓이면 드래그도 무동작.
2. "폴더 내 검색은 Future"라 미뤘지만 **이미 구현되어 있다**. → 스펙대로 하면 기능 제거(회귀).

여기에 **파괴적 동작의 복구 경로 부재**(폴더 삭제 → 노트 대량 휴지통행, 앱 내 복원 UI·IPC 없음)와 **폴더 카드의 물리적 공백**(아이콘·이름·개수만으로 176px 프리뷰 카드 그리드에 들어가면 빈 박스가 된다)이 더해진다. 후자는 타일을 포기하지 않고 해결했다 — 타일을 **그 안의 최근 노트 미리보기**로 채우고(H5), 폴더·노트를 하나의 평면 셀 배열로 가상화한다(H6).

즉 **구조는 맞고, 접지(接地)가 틀렸다.**

## 2. 차단급 결함 (B) — 구현 전 반드시 해소

### B1. `onMoveFolder`가 이동을 하지 않는다 (거짓 성공 토스트)

**증거** — `CardGrid.tsx:232-244`:
```ts
const onMoveFolder = (id: string, folder: string) => {
  void updateMemo(id, null, null)          // ← body/favorite 모두 null. 이동 아님
    .then(() => { …invalidate…; setToast(`→ ${folder || t.folder_root}`); })  // ← 성공 토스트
```
`api.ts:190`에 `moveNote()`가 존재하지만 **호출자가 0건**(`grep moveNote` → 정의 1곳뿐). 주석 자체가 "Until that lands"라 인정한다.
**폴백도 스텁** — `tauri.ts:348-350`: `case "move_note": emitBrowser("memos:changed"); return null;` (파일/스토어 변경 없음).

**영향** — 원본 §2 결정 7("전부 기존 `move_note` IPC 재사용")과 §7("카드 폴더로 이동… 유지")은 사실과 다르다. 사용자는 이동했다고 믿고 토스트를 받지만 노트는 그대로다. P3의 DnD 3종이 모두 이 핸들러를 재사용하도록 설계되어 있어, **P3을 완주해도 이동은 여전히 안 된다.**

**개선** — P0(신설)로 승격:
- `onMoveFolder`를 `moveNote(id, folder)` 호출로 교체, 실패 시 `setError`. 성공 시에만 토스트.
- 폴백 `move_note` 실구현: 대상 메모의 `folder` 필드 갱신 + `oximemo:folders:v1`에 대상 폴더 보장 + `memos:changed` emit.
- 회귀 테스트: 우클릭 이동 후 원래 폴더 목록에서 사라지고 대상에 나타남(폴백 스모크).

### B2. 검색 스코프 회귀 — 있는 기능을 없앤다

**증거** — `CardGrid.tsx:143-145`:
```ts
return base.filter((n) => {
  …
  if (folderFilter !== null && folderFilter !== undefined && n.folder !== folderFilter) return false;
```
즉 **현재 검색은 선택된 폴더로 스코프되며, 그 일치는 이미 직속(`n.folder !== folderFilter`)**이다.

**영향** — 원본 §3.1은 "검색 입력 → 항상 쿼리 모드 전환(전역)", §8은 "폴더 내 검색 = Future"로 규정한다. 그대로 구현하면 폴더 내 검색이 **삭제**된다. §10 수용 기준 8("검색 … 회귀 없음")과 정면 모순.

**개선 — 검색은 모드를 바꾸지 않는다(원본 §3.1 규칙 교체):**

| 상태 | 검색 동작 | 브레드크럼 |
|---|---|---|
| 브라우즈(`""` 또는 경로) + 검색어 | **현재 위치 하위 재귀 검색**(스코프 기본) | `볼트 › 작업` + 검색 칩 `이 폴더 ▾` |
| 브라우즈 + 검색어 + 스코프=전체 | 전역 검색 | 동일 경로 + 칩 `전체 ▾` |
| 쿼리 모드 + 검색어 | 전역 검색 | `검색: {q}` |

- 검색 박스 좌측에 **스코프 칩**(`이 폴더 / 전체`) — Finder의 검색 스코프 바(`This Mac / 폴더명`)와 동형. 기본값은 브라우즈 중이면 `이 폴더`.
- 스코프=`이 폴더`는 **재귀**로 한다(하위 폴더 포함). 검색은 "찾기"이므로 직속 제한은 유효하지 않다 — 현재 코드의 직속 제한은 오히려 버그로 취급하고 재귀로 교정.
- 검색 중에는 폴더 카드 섹션을 숨긴다(결과는 노트 리스트).
- 원본 §8의 "폴더 내 검색(Future)" 항목 삭제.

### B3. 쿼리 모드 "새 폴더"의 자기모순

**모순** — 원본 §4.5: "쿼리 모드에서는 … 볼트 루트에 생성하고 **완료 즉시 해당 위치로 이동하지 않는다**." / §5.3: "폴더 카드가 **이름 선택 상태로 등장** → Enter 확정".
쿼리 모드 화면에는 폴더 카드가 없다(원본 §4.4는 노트 카드만 렌더). 따라서 이름 편집 UI가 나타날 DOM이 없고, 폴더는 `새 폴더`라는 기본 이름으로 사용자 눈에 보이지 않는 곳에 생성된다.

**개선** — 위치 없는 모드에서는 위치 기반 생성을 제공하지 않는다:
- 쿼리 모드의 빈 영역 콘텍스트 메뉴와 헤더 `＋` 드롭다운에서 **"새 폴더" 항목을 렌더하지 않는다**(disabled 아님 — 부재).
- 쿼리 모드의 "새 노트"는 현행 유지(루트 생성 + 상세 열림 → 생성 위치가 상세 화면 폴더 칩에 보이므로 사용자가 즉시 옮길 수 있다).

### B4. 폴더 삭제에 복구 경로가 없다

**증거** — 코어에 `Vault::restore_memo`는 있다(`vault.rs:574`). 그러나 `src-tauri/src/lib.rs`에 `restore*` 커맨드 없음, `api.ts`에 복원 함수 없음, 휴지통 목록 UI 없음. 즉 **앱 내에서 휴지통을 볼 수도, 되돌릴 수도 없다.** 보존 기간 경과 시 `purge`가 하드 삭제한다(`general.trash_retention_days`).

**영향** — 원본 §6.3은 폴더 삭제 시 내용 노트 **전부**를 휴지통으로 보내고, Undo는 §8 Future로 위임한다. 노트 200개 폴더를 오조작 삭제하면 사용자는 Finder로 `.trash`를 직접 파야 한다. 확인 대화 하나로 방어하기엔 손실이 크다.

**개선 — 복구를 같은 페이즈에 넣는다(저비용, 코어 함수 이미 존재):**
1. `delete_folder(path) -> Vec<MemoId>`로 시그니처 변경(휴지통으로 옮긴 노트 id 반환).
2. `restore_notes(ids: Vec<MemoId>)` IPC 신설 — 내부는 `restore_memo` 루프.
3. 삭제 후 토스트에 **"실행 취소" 액션 버튼**(현재 `Toast.tsx`는 메시지 전용이므로 액션 슬롯 1개 추가). 타임아웃 내 클릭 → `restore_notes`.
4. 폴더 자체 복원: 노트 복원이 경로를 보존하므로 폴더는 파일 복원과 함께 재생성된다(빈 폴더였다면 `create_folder`로 재생성).
5. 폴백(`tauri.ts`)도 동일 — `deleted_at` 부여 → 복원 시 해제.

## 3. 높은 위험 (H)

### H5. 폴더 타일은 유지 — 단 176px를 "내용 미리보기"로 채운다 (사용자 결정 반영)

**증거** — `CardGrid.tsx:41-44`: `MIN_COL_W = 240`, `CARD_H = 176`, `ROW_H = 188`. 노트 카드는 본문 프리뷰 카드다. 원본 §4.2의 폴더 카드(아이콘·이름·개수뿐)를 그대로 176px에 넣으면 **120px 이상이 공백**이 된다. Finder에서 폴더·파일 타일이 동일 크기인 것은 둘 다 프리뷰가 없기 때문이므로, 그 근거는 이 앱에 적용되지 않는다.

**해법 — 비우지 말고 채운다.** macOS 폴더 아이콘이 내부 항목 썸네일을 겹쳐 보여주고 Windows 탐색기가 폴더 썸네일을 합성하는 것과 같은 계보: **폴더 타일 = 그 안의 최근 노트 미리보기.**

```text
┌────────────────────────────┐ 176px, 노트 카드와 동일 폭·반경·보더
│ 📁 회의록               12 │  헤더: 폴더색 아이콘 + 이름 + 재귀 노트 수
│ ─────────────────────────  │
│ 주간 스프린트 회고          │  최근 노트 제목 ≤3 (13px, text-muted)
│ 2026-Q4 로드맵 확정         │  ← 행 클릭 = 그 노트 바로 열기
│ 인터뷰 정리 — 김OO          │
│                            │
│ 폴더 2 · 3일 전             │  푸터: 하위 폴더 수 + 최근 활동
└────────────────────────────┘
```

**노트 카드와의 구분**(색 코딩 없이, 형태로):
- 본문 프리뷰 문단이 없다 → 대신 **제목 행 목록**. 실루엣이 다르므로 즉시 식별된다.
- 상단 좌측에 **폴더 탭 노치**(`::before`, 3px 높이 · 28px 폭 · 상단 모서리만 반경) — 종이 폴더 은유. 저비용 CSS.
- 배경은 노트 카드(`surface-raised`)보다 **한 단계 낮은 톤** — 컨테이너 느낌. 보더·반경·호버는 동일.

**목업 검증** (`assets/2026-08-20-folder-tile-mockup.html`, 실제 토큰·카드 크롬으로 A/B/C/C2 병렬 렌더):
- A(원본 스펙)는 예측대로 **빈 박스**로 읽힌다 — 기각 확인.
- C는 노트 카드와 밀도가 맞고, 제목 3행 + 푸터가 176px를 안정적으로 채운다. 빈 폴더도 CTA로 채워져 어색하지 않다.
- **다크에서는** 폴더 타일(`surface` 0.13)이 노트 카드(`surface-raised` 0.22)보다 어두워 구분이 즉시 성립한다.
- **라이트에서는** `surface`(0.985)와 `surface-raised`(1.0)의 차이가 거의 식별되지 않는다. → 테마별로 값을 다르게 잡아야 한다.
- **결정**: 신규 토큰 `--folder-tile-bg` — 라이트 `var(--color-surface-muted)`(0.96), 다크 `var(--color-surface-sunken)`(0.11). 하드코딩 금지, `tokens/semantic-*.css`에 정의.

**빈 폴더 타일**: 본문 자리에 `비어 있음` + `＋ 새 노트` 인라인 버튼(진입 없이 즉시 생성). 공백이 CTA가 된다.

**상호작용**
- 타일 헤더·빈 영역 클릭 → 폴더 진입.
- 최근 노트 행 클릭 → **그 노트를 바로 열기**(`stopPropagation`). 2단계 이동을 1단계로 줄이는 실질 이득이며, 타일이 176px를 차지할 정당성이 된다.
- 호버·포커스 링은 기존 카드 규칙 재사용.

**필요 데이터 — 신규 IPC `folder_children(path)`**
```rust
pub struct FolderCard {
    pub path: String,            // "작업/2026"
    pub note_count: u32,         // 직속 (기존 list_folders 값)
    pub note_count_deep: u32,    // 재귀 — 타일에 표시 (M11 동시 해결)
    pub subfolder_count: u32,
    pub recent: Vec<RecentNote>, // ≤3, newest-first: { id, title, updated_at }
}
```
- 구현: `list_folders`의 직속 카운트로 재귀 카운트를 프리픽스 합산(`BTreeMap` 순회, 추가 I/O 0) + `by_sort` 인덱스를 newest-first로 순회하며 각 표시 대상 자식에 최근 3건 수집. `by_sort`는 이미 **newest-first 정렬**(`store/index.rs:5-9`)이고 `IndexRecord`에 `title`·`path`가 있으므로(`26-40`) 추가 파일 I/O 없음.
- **조기 종료**: 재귀 카운트가 0이 아닌 모든 자식이 3건을 채우면 순회 중단. 통상 수십 레코드에서 끝난다.
- 노트는 **가장 가까운 표시 대상 조상**에 귀속된다 — 루트에서 볼 때 `작업/2026/x.md`는 `작업` 타일의 미리보기·카운트에 반영된다. 이것이 M11("중간 폴더가 노트 0으로 보임")을 근본 해결한다.
- 캐시: TanStack `["folderChildren", path]`. `memos:changed`가 이미 무효화 대상에 `["folders"]`를 포함하므로(`CardGrid.tsx:200`) 같은 자리에 키 추가.
- 폴백(`tauri.ts`): localStorage 메모 배열을 `updated_at` desc 정렬해 동일 로직으로 산출(추가 저장소 불필요).

### H6. 가상화 offset — 폴더를 같은 셀 배열에 넣어 문제 자체를 없앤다

**증거** — `useVirtualizer({ count: rowCount, getScrollElement: () => scrollerRef.current, estimateSize: () => ROW_H })`(`CardGrid.tsx:179-184`). 가상 아이템은 스크롤러 기준 절대 오프셋으로 배치되므로, 스크롤러 상단에 비가상 섹션을 넣으면 **모든 노트 행이 그 높이만큼 겹친다.** 원본 §4.2는 "가상화 목록 위에 비가상 행"으로 넘겼다.

**개선 — 별도 섹션도, `scrollMargin` 보정도 두지 않는다.** 폴더 타일이 노트 카드와 **동일 높이(176px)**이므로 하나의 평면 셀 배열로 합칠 수 있다:
```ts
type Cell = { kind: "folder"; folder: FolderCard } | { kind: "note"; note: MemoSummary };
const cells: Cell[] = [...folderCells, ...noteCells];   // 폴더 우선
const rowCount = Math.ceil(cells.length / cols);        // ROW_H 균일 유지
```
- `GridView`가 셀 `kind`로 분기 렌더. virtualizer 설정·행 높이 계산·무한 스크롤(`fetchNextPage`) 로직 **무변경**.
- 폴더는 고정 프리픽스, 노트는 페이지 추가 → 행 수만 늘어나므로 커서 페이징과 충돌 없음.
- 폴더가 그리드에 자연스럽게 wrap된다(진짜 Finder 배치). 원본이 원했던 "혼합"이 여기서 정확히 성립한다.
- **폴더 과다 대응**: 폴더 셀이 2행을 넘으면 `2*cols - 1`개만 표시하고 마지막 셀을 `폴더 N개 모두 보기`로. 펼침은 위치별 세션 한정 상태.
- 리스트 뷰는 원본대로 폴더 행 → 노트 행(행 높이 균일해 그대로 성립).

### H7. 브레드크럼 바 폭 예산이 없다

**실측 합산** — 헤더 `h-12`, `gap-3`(12px)×4, 검색 `w-56`(224), 뷰 스위처 4개 라벨 버튼(`px-2.5` + 텍스트 "timeline" 등 ≈ 200), 자물쇠(24+4), `＋`+`HTML` 분할 버튼(28+26), 설정(≈28) → **우측 컨트롤만 약 560–590px**. 창 1000px에서 사이드바(≈220px, `Sidebar.tsx` 고정폭) 제외 시 콘텐츠 780px → **브레드크럼 가용 폭 190–220px**. `볼트 › 작업 › 2026-Q4`(≈180px)에서 이미 한계, 한글 폴더명 2단계면 초과.

**개선 — 우측을 먼저 줄인다:**
1. 뷰 스위처를 **아이콘 4개**(`LayoutGrid / List / Clock / Network`, 각 24px)로 교체 → 200px → 100px. 라벨은 `title`/`aria-label`로 유지.
2. 브레드크럼 오버플로: 가용 폭 초과 시 `루트아이콘 › … › 부모 › 현재`(양끝 우선, 중간 축약). 원본의 "앞쪽부터 축약"보다 방향 감각이 유지된다.
3. 콘텐츠 폭 < 640px: 검색을 아이콘 버튼으로 접고 클릭 시 헤더를 검색 전용 행으로 전환(Escape로 복귀).
4. 자물쇠는 브라우즈 모드에서만 렌더(원본 유지) → 쿼리 모드에서 28px 회수.

### H8. Escape 과적재 — 내비게이션에서 제거

Escape는 이미 상세 다이얼로그·캡처 오버레이 닫기에 쓰이고, 검색 입력 클리어 기대도 있다. 원본 §3.2는 여기에 "한 레벨 위"를 더해 3중 의미로 만든다. Finder에서 상위 이동은 `⌘↑`이고 Escape는 취소다. 위치 이탈은 **취소가 아니라 이동**이므로 Escape에 실으면 오조작 시 맥락을 잃는다.

**개선** — Escape: (1) 다이얼로그/오버레이 닫기 → (2) 검색어 클리어(`localSearch`+`debounced`+`search` 3개 동시 리셋 필요) 까지만. 상위 이동은 `⌘↑` 단독. `⌘↓`는 셀렉션 모델 부재로 미할당(원본과 동일).

### H9. `""`(루트) vs `null`(쿼리) 분리가 기존 뷰 핀 설정을 재해석한다

**증거** — `CardGrid.tsx:107` `setFolderView(folderFilter ?? "", v)`, `295-297` `isLocked`도 `folderFilter ?? ""`. 현재 **"전체 보기"와 "루트"는 같은 `FolderDef{path:""}` 엔트리를 공유**한다. 원본이 두 상태를 분리하면 기존 사용자가 "전체 보기"에 걸어둔 핀이 "루트 브라우즈" 핀으로 바뀐다. 또한 원본은 쿼리 모드에서 자물쇠를 숨기라고만 하고 **쿼리 모드의 뷰 모드를 어디에 저장할지 정의하지 않는다.**

**개선**
- `FolderDef{path:""}`는 **루트 브라우즈 전용**으로 계승(의미가 가장 가깝다). 마이그레이션 코드 불필요, 동작 변화는 문서화만.
- 쿼리 모드 뷰는 폴더 속성이 아니므로 `localStorage["oximemo.queryView"]`에 저장(세션 간 유지, config 오염 없음). 자물쇠는 계속 숨김.
- `useEffect`(CardGrid:97-100)의 핀 동기화는 브라우즈 모드에서만 동작하도록 가드.

### H10. 트리 제거의 대체 조망 수단이 없다

트리는 `depth<1` 자동 펼침 + 개수로 **볼트 전체 구조를 한 화면에** 보여줬다(`Sidebar.tsx:79`). 원본의 대체는 브레드크럼(현재 경로만) + 고정 폴더(수동 큐레이션)뿐이다. 신규 사용자는 고정이 0개라 사이드바 FOLDERS 섹션이 비고, 3단 이상 계층에서 "어디에 뭐가 있나"를 잃는다. 원본 §1.3은 트리 병존을 "중복"으로 기각했지만, 기각의 대가를 메우지 않았다.

**개선 3종 — 전부 저비용, 선례 있음:**
1. **브레드크럼 세그먼트 드롭다운** (Windows 탐색기 표준): 각 세그먼트에 `▾`. 클릭 시 그 레벨의 **형제 폴더 목록** → 임의 점프. `list_folders` 결과를 프리픽스로 필터하면 추가 IPC 0.
2. **"폴더로 이동" 팔레트 `⌘⇧O`**: 전체 폴더 fuzzy 검색 점프(현재 앱에 팔레트 없음 — `⌘K` 미존재 확인). 노트가 아닌 **폴더 전용 점프**로 범위를 좁혀 저비용 유지. `move_note`의 "폴더로 이동…" 서브메뉴(폴더 많으면 사용 불가)도 이 팔레트로 대체 가능.
3. **최초 고정 시드**: 고정이 0개이고 최상위 폴더가 있으면 사이드바 FOLDERS 섹션에 **최상위 폴더 전체를 자동 표시**(암시적 고정, `pinned` 미설정 상태). 사용자가 하나라도 명시적으로 고정/해제하면 그 순간부터 명시 목록만 사용. → 빈 섹션과 "고정을 몰라서 못 쓰는" 문제를 동시 해결.
