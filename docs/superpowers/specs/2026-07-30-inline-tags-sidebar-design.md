# oxinot — 인라인 `#태그` + 사이드바 탐색 재설계

- **Date:** 2026-07-30
- **Status:** Draft (디자인 확정, 구현 계획 대기)
- **Scope:** 데스크톱 프론트엔드 + Rust 코어 + Tauri 브리지. 단일 기능("인라인 태그 + 사이드바 탐색").
- **비주얼 참고:** `.superpowers/brainstorm/*/content/` 목업들(셸 레이아웃, 3상태 필터, 에디터 기법).

## 1. 배경 & 목표

현재 oxinot은 태그를 본문과 분리된 `tags: Vec<String>` 필드로 두고, 캡처/편집 화면 하단의 `TagInput` 칩 편집기로 수동 입력한다. 필터는 헤더 chip으로 노출되지만 **로딩된 페이지의 태그만** 계산돼 전체 태그 목록이 아니고, 색상 필터·사이드바도 없다.

목표:

1. **입력 마찰 제거** — 본문에 `#태그`를 쓰면 자동 인식(태그 입력창 제거). Apple Notes/Bear 방식.
2. **강력한 탐색** — 접이식 사이드바에서 전체 태그(건수)·색상을 3상태 복합 필터로 걸러보기.
3. **일관된 시각 언어** — 태그=주황 app-wide, 즐겨찾기는 별 아이콘만.

## 2. 결정 요약 (locked)

## 3. 태그 추출 규칙

본문에서 태그 토큰을 뽑는 정규식(서버 Rust·클라이언트 TS **동일 패턴**, lookbehind 미사용 — Rust `regex` crate 미지원):

```
(^|[\s\p{P}])#([\p{L}\p{N}_]+)
```

- 캡처 그룹 2가 태그 토큰. 그룹 1(선행 구분자)은 치환 시 보존.
- **선행 구분자 가드**: `#` 바로 앞이 글자/숫자(`\p{L}\p{N}`)이면 태그 아님.
  - `#악보` (공백/줄머리 선행) → 태그 `악보` ✓
  - `C#m7` (`C` 선행) → **태그 아님** ✓ (사용자 실제 데이터 근거)
  - `#a#b` → `a`만 (`#b`의 선행이 글자 `a`) — 모호 케이스에서 가드와 일관.
- **마크다운 제목 안전**: `# Heading`은 `#` 직후 공백이라 토 없음 → 미매칭.
- **토큰 문자**: 유니코드 글자/숫자/`_`. 공백·구두점에서 절단(`#태그,` → `태그`). `/`,`-` 미포함(중첩 태그는 비목표).
- **정규화**: 추출 토큰 → NFC + 소문자 변환하여 `tags` 배열/사이드바에 저장. 본문 표시 케이스는 보존(미러 하이라이터는 본문 리터럴을 강조).
- **알려진 사소한 오태(미처리, v1)**: `#fff` 같은 hex 토도 태그로 잡힘. 드물고 편집으로 제거 가능 → 향후 정제.

> 클라이언트 미러 하이라이터와 서버 추출이 **반드시同一 정규식**을 써야 강조≠저장 불일치가 안 생긴다. 양측에 패턴을 상수로 두고 동기화.

## 4. 데이터 모델 & API 변경

### 4.1 태그는 본문에서 파생 (단일 진실 공급원 = 서버)

- `Vault::create_note(body, color)` — `tags` 인자 제거. 내부에서 `tags = extract_tags(&body)`.
- `Vault::update_note(id, body, favorite, color)` — `tags` 인자 제거. `body = Some` 이면 태그 재파생, `None`(메타 전용 갱신)이면 기존 `note.tags` 유지.
- Tauri 명령 `create_note`/`update_note`에서 `tags` 인자 제거. 프론트 `api.ts` 시그니처 동기화.
- 부수효과: CLI로 본문에 `#태그` 작성 시에도 자동 태깅됨.
- 미러 편집기는 **순수 시각** 레이어. 저장 시 프론트는 원문 body만 전송, 백엔드가 파생.

### 4.2 facets 집계 (신규)

- `Vault::list_facets() -> Facets { tags: Vec<(String,u32)>, colors: Vec<(String,u32)> }`
  - 인덱스(redb) 레코드(`NoteRecord`의 tags/color)를 스캔해 메모리 집계. 로컬 규모에 충분.
- Tauri 명령 `list_facets` 추가. 프론트 사이드바는 이를 사용(현재의 "로딩 페이지 distinct tags" 로직 제거).

### 4.3 복합 필터를 서버 측으로

`NoteFilter` 확장:

```rust
pub struct NoteFilter {
    pub include_tags: Vec<String>,  // 비어있으면 무조건 통과
    pub exclude_tags: Vec<String>,
    pub match_all: bool,            // true=AND, false=OR (include_tags에)
    pub colors: Vec<String>,        // 비어있으면 무조건 통과, 아니면 색 소속(OR)
    pub favorites_only: bool,
    pub include_deleted: bool,
}
```

- 매칭: `include_ok && exclude_ok && color_ok && favorites_ok`
  - `include_ok` = include 비었거나 (match_all ? 모두 보유 : 하나 보유)
  - `exclude_ok` = exclude의 어떤 태그도 안 가짐
  - `color_ok` = colors 비었거나 note.color ∈ colors
- `list_notes` 시그니처를 이 필터로 교체. 페이지네이션과 무관하게 정확.
- **BM25 검색 경로**: 검색 결과 위 복합 필터는 기존처럼 클라이언트 적용(스코프 제한). 문서화.
- 기존 단일 `tag` 인자/`tauri.ts`의 `tag` 분기는 새 구조로 마이그레이션.

### 4.4 해시 함수 변경

`hash_note(body, favorite, color)` — `tags` 인자 제거. 태그가 본문에서 파생되므로 body 해시가 태그 변경을 이미 포함 → 별도 tags 해싱은 중복.

- 갱신 호출부: `vault.rs`(create/update/soft_delete/restore), `store/files.rs`(읽기 경로 해시 재계산).
- **기존 테스트 수정 필수**: `hash::tests::metadata_only_edit_changes_hash`의 "동일 body + 태그 추가 → 해시 변경" 단언은 전제(태그⊥body)가 성립 불가 → 제거. favorite/color 단언 유지. "body에 `#x` 포함 여부로 해시 변경" 단언 추가.

### 4.5 검색 인덱스

- tantivy `tags` 필드는 파생 tags로 계속 채움(정규화 토큰). `#태그` 검색·정확 태그 필터 보조. body에도 원문 `#태그`가 있으므로 중복되지만 무해.

## 5. 마이그레이션 (레거시 태그) — **결정: 없음 (손실 수용)**

구 UI는 본문에 없어도 `TagInput`으로 태그를 추가 가능했으므로, 기존 노트 중 **본문에 `#토큰`으로 안 담긴 태그**가 존재할 수 있다. "본문 = 단일 진실"로 전환 시 이는 다음 저장에서 파생으로 소실된다.

**결정: 마이그레이션 없음, 손실 수용.** 앱은 프리릴리즈(v0.2.0, 단일 사용자 로컬)이므로 레거시 데이터 정합성을 보장하지 않는다. 본문에 `#토큰`으로 담긴 태그만 생존하고, 고아 레거시 태그는 다음 `update`/`reindex` 시 사라진다. 구현은 1회 마이그레이션·플래그·본문 보강 로직을 일절 포함하지 않아 단순하다.

> 부수 정리: `read_note`가 본문에서 태그를 재파생하므로, 사용자가 `oxinot reindex`를 한 번 돌리면 인덱스의 레거시 태그도 파생값으로 정렬된다(선택적, 자동 아님).

## 6. 편집기 — textarea + mirror overlay (B)

구조: 투명 텍스트의 `<textarea>`(z-index 2, caret만 가시) 뒤에 칩을 렌더한 `<div>`(mirror, z-index 1, pointer-events none)를 정확히 겹침. 동일 폰트/패딩/`white-space:pre-wrap`/줄바꿈으로 정렬. 스크롤 동기화.

- 입력·IME·Cmd+Z·붙여넣기·선택영역 = 브라우저 네이티브 textarea.
- **한글 IME 하드 요건**: 미러는 매 input마다 원문→강조 HTML을 재생성하지만, textarea 자체는 건드리지 않으므로 조합형 입력이 깨지지 않음. (contentEditable이었다면 `compositionstart/end` 게이트가 필수였음 — B 채택으로 구조적 회피.)
- 감지 태그 표시: 미러와 별개로 본문 value에서 `extract_tags`로 칩 목록 렌더(선택).
- 공유 컴포넌트 `NoteComposeForm`/`TagInput` 변경:
  - `TagInput` 제거(파일 삭제). `NoteComposeForm`에서 `tags`/`onTagsChange`/`tagPlaceholder` props 제거, 하단 스트립 = 색상 + 확인만.
  - 본문 `<textarea>`를 미러 편집기 컴포넌트(`MirrorTagEditor`)로 교체. 캡처 오버레이·노트 상세 양쪽 동일 사용.
- **인라인 칩 클릭→필터는 v1 비목표**: mirror 기법에서 textarea가 클릭을 가로채므로 히트테스팅이 필요. 사이드바가 필터 UI를 담당하므로 연기. 향후 클릭 좌표→칩 히트테스트로 보강 가능.

## 7. 사이드바

레이아웃: `flex` 행 = [사이드바 | 메인(헤더+그리드)]. 사이드바 폭 ~220–248px, 접기 가능.

섹션(위→아래):

1. **모든 노트** (전체 건수) — 기본 선택.
2. **즐겨찾기** (건수) — 별 아이콘.
3. **태그** — `list_facets`의 tags를 칩으로. 각 칩 = 3상태(§4.3 include/exclude). 건수 표시(전역, 비필터 기준). 상단 `선택된 태그 중 모두 포함 ⇅` 토글(match_all). `모든 태그` 버튼 = 태그 선택 초기화.
4. **색상** — `list_facets`의 colors를 swatch로. 다중 선택(OR 소속). 선택 swatch는 링 표시.
5. 하단 **사이드바 숨기기** 토글.

- **접기 상태**: ui store + localStorage 영속. 접으면 그리드 전폭 + 헤더에 펼치기 아이콘.
- **필터 변경 시** 스크롤 상단 리셋(기존 동작 유지).
- 활성 필터 요약: 헤더 또는 사이드바 상단에 "N개 태그 선택 · M개 메모" + 설명 문장(포함 단색/제외 취소선) — 애플 패턴.

## 8. 헤더 / 검색 / 카드 / 팔레트 일관성

- **검색**: 헤더 유지(트랜지언트 액션). 사이드바는 탐색.
- **헤더**: 트래픽라이트 클리어(`pl-[76px]`), 드래그 영역, 검색, 새 노트, 설정, 테마. 태그 chip들은 헤더에서 제거(사이드바로 이동).
- **카드 태그 칩**: 기존 zinc → 태그 악센트(주황 텍스트 + 연한 주황 배경)로 통일.
- **즐겨찾기**: 별 아이콘만 사용, 주황 미사용(태그와 의미 분리).

## 9. 비목표 (향후)

- 폴더 / 중첩 태그 / 스마트 필터(저장된 검색).
- 인라인 칩 클릭→필터(§6).
- hex 토큰 오깅 정제(§3).
- 검색 경로 서버 측 복합 필터(§4.3, 현재 클라이언트).

## 10. 검증 계획

- **Rust 단위**: `extract_tags` — `#악보 #장범준`, `C#m7`/`F#m7`(미매칭), `# Heading`(미매칭), 한글, 대소문자 정규화, 인접 `#a#b`. 해시 테스트 개정(§4.4). `NoteFilter` 복합 매칭(AND/OR/제외/색상).
- **빌드**: `cargo build`/`clippy` 경고 0, `tsc -b` + Vite.
- **수동**: 캡처 오버레이 미러 + **한글 조합 입력** 스트레스(커서 안 튀는지), 사이드바 3상태 + AND/OR + 색상 + 접기 영속, facets 건수 정확성. 레거시 태그는 마이그레이션 없이 다음 저장/`reindex` 시 파생으로 정리됨을 확인(고아 태그 소실 = 의도).
- **재배포**: 프론트 변경이므로 `cargo build -p oxinot-desktop --release` + 앱 교체 + 재서명 필요(임베드 프론트 갱신).
