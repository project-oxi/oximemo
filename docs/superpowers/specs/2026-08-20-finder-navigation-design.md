## 1. 배경

### 1.1 문제 — 두 패러다임의 잔재가 혼재

oximemo는 "폴더 없이 태그로만 분류하는 메모 앱"에서 "물리적 폴더 계층을 가진 통합 노트 앱"(v3, migrate.rs)로 전환됐다. 전환 후 UI는 두 패러다임이 뒤섞였다:

| 증상 | 현재 동작 | 문제 |
|------|----------|------|
| 폴더가 메인에 안 보임 | 메인 영역은 노트 카드만 렌더. 폴더는 사이드바 트리에서만 존재 | 탐색기가 아니라 "필터된 검색 결과 화면". 루트에 폴더 1 + 메모 2가 있어도 폴더는 안 보임 |
| 사이드바가 진짜 내비게이션 | 폴더 트리에서 폴더 클릭 = 유일한 폴더 진입법 | Finder의 즐겨찾기·필터 공간이 아니라 파일 브라우저 역할을 중복 수행 |
| 계층 이동 수단 없음 | 폴더 안에 들어가면 위로 가는 방법이 사이드바의 부모 노드 클릭뿐 | 브레드크럼 없음, 백 스택 없음 |
| 폴더·노트 조작이 흩어짐 | 생성은 설정/에디터/사이드바+ 곳곳, 이동은 서브메뉴 하나 | 우클릭 콘텍스트 메뉴(탐색기의 핵심 조작면) 부재, 드래그 앤 드롭 부재 |

### 1.2 채택된 방향 — Finder의 3면 구조

macOS Finder / Files 앱 / OneDrive가 정립한 모델을 취한다:

```
┌─ 사이드바 ──────┐┌─ 브레드크럼 바 ─────────────────────────────┐
│ 스마트 컬렉션   ││ 📁 Vault › 작업 › 2026-Q4    [검색][뷰][＋][⚙]│
│ 폴더 즐겨찾기   │├─ 메인 영역 (현재 위치의 내용물) ─────────────┤
│ 태그            ││ 📁 회의록   📁 참고자료   │ 노트카드 노트카드 │
└────────────────┘└──────────────────────────────────────────────┘
```

1. **사이드바 = 큐레이션·필터 공간** (즐겨찾기, 스마트 컬렉션, 태그). 계층 탐색 아님.
2. **메인 영역 = 현재 위치의 내용물** (폴더 카드 + 노트 카드 혼합, 폴더 우선 정렬).
3. **브레드크럼 = 위치의 단일 진실 원천** (세그먼트 클릭으로 임의 레벨 점프).

검증 근거: 브레드크럼은 계층 제품의 표준 이동 수단(임의 레벨 점프, [Smashing Magazine](https://www.smashingmagazine.com/2022/04/breadcrumbs-ux-design/), [Pencil & Paper](https://www.pencilandpaper.io/articles/breadcrumbs-ux)); 폴더/파일 혼합 + 폴더 우선 정렬은 Files 앱의 Cards/Grid 레이아웃([Files docs](https://files.community/docs/customize-settings/layout)); "드래그해서 폴더에 드롭 = 이동"은 Obsidian·Apple Notes·Notion 공통 표준([Apple 지원](https://support.apple.com/guide/notes/add-and-remove-folders-apd558a85438/mac), [Obsidian 포럼](https://forum.obsidian.md/t/move-note-by-dragging-link-into-a-folder/45552)).

### 1.3 기각된 방향

- **Finder식 탭(⌘T)** — 노트 상세가 다이얼로그 오버레이(§7.3 설계 고정)라 탭의 이득이 창 관리뿐이고, 구현 비용(탭 상태, 위치 동기화, DnD 간 탭 전환)에 못 미친다. Future로 명시만 한다(§8).
- **Obsidian식 사이드바 파일 트리 유지 + 메인에도 폴더 표시** — 내비게이션이 두 곳에 중복되어 혼재가 해소되지 않는다. 사용자 지시("사이드바는 즐겨찾기와 필터 공간")와도 배치.
- **더블클릭 진입(Finder 엄격 호환)** — 본 앱은 웹식 상호작용(싱글 클릭 = 열기)으로 일관되게 왔다. 폴더만 더블클릭을 요구하면 학습 비용이 이중이 된다. **싱글 클릭 = 폴더 진입**으로 통일.

## 2. 핵심 결정 (locked)

| # | 결정 | 근거 |
|---|------|------|
| 1 | **내비게이션은 두 모드** — 브라우즈(위치 기반) / 쿼리(필터 기반) | 폴더 계층 탐색과 전역 검색·즐겨찾기·태그는 본질이 다른 작업. 하나의 상태로 억지로 통합하면 현재의 혼재가 재발한다. |
| 2 | **`folderFilter`가 위치 필드가 된다** — `null` = 쿼리 모드, `""` = 볼트 루트 브라우즈, 경로 = 해당 폴더 브라우즈 | 기존 타입(`string \| null`)과 시맨틱을 그대로 계승해 마이그레이션 비용 최소. `null`이던 "전체 메모"는 쿼리 모드의 스마트 컬렉션으로 명명된다. |
| 3 | **폴더 내용은 직속 자식만** — 브라우즈 모드에서 하위 폴더 노트는 재귀 표시 안 함 | Finder 시맨틱. 현재 백엔드 `folder_matches`는 재귀(`novel` = `novel/**` 전체)라 MemoFilter에 immediate 모드를 추가한다(§6.1). 참고: 브라우저 폴백은 이미 직속 일치라 오히려 불일치가 해소된다. |
| 4 | **폴더 카드가 메인에 섞인다** — 그리드/리스트에서 폴더는 항상 노트 앞에 정렬 | Finder/Files 표준. Timeline/Graph는 분석 뷰이므로 노트 전용(폴더 미표시). |
| 5 | **브레드크럼 바가 CardGrid 헤더를 대체** — 경로 세그먼트 + 검색 + 뷰 스위처 + 새로 만들기 + 설정 | 위치 표시는 내용물 위 단일 행이어야 한다. 별도 행 추가가 아닌 기존 헤더 재구성. |
| 6 | **사이드바 폴더 트리 제거** — 폴더 즐겨찾기(고정) 섹션으로 대체, 백엔드 `FolderDef.pinned` 신설 | §1.2-1. 고정은 폴더 카드 우클릭 또는 설정에서. |
| 7 | **노트 이동은 3계층** — ① DnD(노트→폴더 카드/브레드크럼 세그먼트/사이드바 고정 폴더) ② 우클릭 "폴더로 이동…" 서브메뉴(기존) ③ 상세 화면 폴더 칩(기존) | 드래그는 표준이지만 보이는 폴더가 없을 때/키보드 사용자를 위해 서브메뉴·칩이 필요. 전부 기존 `move_note` IPC 재사용. |
| 8 | **콘텍스트 메뉴 3종** — 빈 영역(새 노트 MD/HTML, 새 폴더), 폴더 카드(열기/이름 변경/사이드바 고정/삭제), 노트 카드(기존 유지) | Finder의 핵심 조작면. 새 폴더는 이미 구현된 낙관적 생성 모델(commit `b5be6ba`)을 메인 영역으로 이식. |
| 9 | **폴더 이름 변경·삭제는 실제 백엔드 명령으로** — `rename_folder`, `delete_folder`(내용 노트는 휴지통행 후 폴더 제거) | 빈 폴더 create+delete 편법은 이름 변경에 실패하고, "내용 있으면 삭제 거부"는 Finder 경험과 어긋난다. |
| 10 | **탭·멀티셀렉트·⌘X/⌘V 이동·폴더 DnD·정렬 메뉴는 Future** — 이 설계에 포함 안 함 | §8. 스코프 통제. 멀티셀렉트 없는 ⌘X/⌘V는 셀렉션 모델을 먼저 요구한다. |

## 3. 내비게이션 상태 모델

### 3.1 상태 정의 (`stores/ui.ts`)

```ts
/** Browsing location: "" = vault root, "a/b" = that folder.
 *  null = query mode (smart collection / search / favorites / tags). */
folderFilter: string | null;
```

변경 자체는 없다(타입 동일). **해석**이 바뀐다:

| folderFilter | 모드 | 메인 내용물 | 브레드크럼 |
|---|---|---|---|
| `null` + 검색어 | 쿼리 | 검색 결과(전역, 재귀) | `검색: {q}` |
| `null` + favoritesOnly | 쿼리 | 즐겨찾기 노트 | `즐겨찾기` |
| `null` + 태그 필터 | 쿼리 | 태그 매칭 노트(전역) | `태그 #a #b` |
| `null` (아무것도 없음) | 쿼리 | 전체 노트(전역) | `모든 노트` |
| `""` | 브라우즈 | 루트 직속 폴더 + 루트 loose 노트 | `볼트` 아이콘 |
| `"작업/2026"` | 브라우즈 | `작업/2026` 직속 하위 폴더 + 직속 노트 | `볼트 › 작업 › 2026` |

규칙:
- 태그 클릭·즐겨찾기 진입은 **항상 쿼리 모드로 전환**(`setFolderFilter(null)`). 계층 위치는 버리는 대신 쿼리 결과 카드에 폴더 칩으로 위치를 보여준다(§4.4). 검색 입력은 전환하지 않는다(아래).
- ~~브라우즈 중 검색은 전역 검색으로 전환한다(폴더 내 검색은 Future).~~ **[리뷰 §2 B2에서 기각]** — 폴더 내 검색은 이미 구현되어 있다(`CardGrid.tsx:145`). 검색은 모드를 전환하지 않고, 스코프 칩(`이 폴더`(재귀)/`전체`)이 범위를 정한다. 태그 클릭은 쿼리 모드 전환을 유지.
- **앱 기본 시작 화면 = 볼트 루트 브라우즈**(`folderFilter: ""`). 현재 기본값 `null`(전체 메모)에서 변경. "모든 노트"는 사이드바 스마트 컬렉션으로 명시적 진입.

### 3.2 폴더 진입·복귀

- 폴더 카드 클릭 → `setFolderFilter(path)`, 스크롤 상단(기존 동작).
- 브레드크럼 세그먼트 클릭 → 해당 경로로.
- 브레드크럼 루트 아이콘 클릭 → 루트.
- `Escape`(메인 영역 포커스, 다이얼로그 닫힘 상태): 검색 중이면 검색 해제, 아니면 한 레벨 위(`a/b` → `a`, `a` → `""`, `""` → 유지).
- `⌘↑` 한 레벨 위, `⌘↓` 선택 없이는 생략(셀렉션 모델 없음).
- 백/포워드 히스토리 스택은 v1 제외 — 브레드크럼이 임의 레벨 점프를 커버(§8 Future).

## 4. UI 스펙

### 4.1 브레드크럼 바 (CardGrid 헤더 재구성)

```text
[📁 볼트] › [작업] › [2026-Q4]        [🔍 검색…] [Grid|List|Timeline|Graph] [🔒] [＋ 새 노트 ▾] [⚙]
```

- 경로 세그먼트: `nav` 스타일(`text-[13px] text-text-muted hover:text-text`), 구분자 `›`(`text-text-subtle`). 현재(마지막) 세그먼트는 `text-text font-semibold`이고 비클릭.
- 루트 세그먼트는 볼트 아이콘 + 앱명("OxiMemo") 대신 **아이콘만** — 너비 절약, aria-label `볼트 루트`.
- 쿼리 모드: 세그먼트 하나(모드 라벨) + 좌측에 검색 아이콘 대신 컬렉션 아이콘( Layers/Star/Hash/Search). 클릭 비활성.
- 경로가 헤더 폭을 넘기면 **앞쪽부터 `…`으로 축약**(`… › 작업 › 2026-Q4`) — 전체 경로는 title 툴팁.
- 접근성: `nav[aria-label="경로"]` + `aria-current="page"`(마지막 세그먼트) — 브레드크럼 ARIA 표준.
- 기존 컨트롤(검색 박스, 뷰 스위처, 뷰 핀 자물쇠, 새 노트 분할 버튼, 설정)은 우측에 그대로 재배치. 뷰 핀 시맨틱: **브라우즈 모드에서 현재 위치별 핀, 쿼리 모드에서는 자물쇠 숨김**(핀은 물리적 폴더 속성이므로).

### 4.2 메인 영역 — 내용물 렌더링

그리드/리스트 뷰(폴더 표시 뷰):

```text
┌──────────┬──────────┬──────────┬──────────┐
│ 📁 회의록 │ 📁 참고  │ ┌────────┐│ ┌────────┐│
│  노트 12 │  노트 4  │ │노트카드 ││ │노트카드 ││
└──────────┴──────────┴ └────────┘┘ └────────┘┘
```
- 폴더 카드 클릭 = **폴더 진입**(§3.2). 노트 카드 클릭 = 기존과 동일하게 **상세 다이얼로그 열기**.
- **폴더 섹션**: 가상화 목록 위에 비가상 행(폴더 수는 화면당 몇십 수준). 가로 스크롤 아님 — 노트 그리드와 동일 컬럼 폭, `grid` 배치.
- **폴더 카드**: 폴더 아이콘(`colorForFolder` 색, 카드 대비 1단계 큰 16px) + 이름(첫 줄) + `노트 {n}`(직속 노트 수, `note_count` 재사용). 노트 카드와 동일 반경·보더·호버. 프리뷰 본문 없음 — 시각적으로 노트 카드와 구분되는 것은 아이콘과 개수뿐(과도한 차별화 금지, Finder도 파일런과 폴더런의 차이는 아이콘뿐).
- **리스트 뷰**: 폴더 행 = 아이콘 + 이름 + `—`(날짜 칼럼 자리) + `{n} 항목`. 노트 행과 동일 그리드.
- 폴더 정렬: 이름 localeCompare. 노트 정렬: 기존(업데이트 desc).
- 빈 폴더도 표시(`노트 0`).
- Timeline/Graph 뷰: 폴더 미표시, 노트 전용(기존 유지). 이 뷰들은 "분석 뷰"로 브라우즈 모드에서도 현재 위치의 **재귀** 노트를 보여준다(immediate=false) — 타임라인에서 하위 폴더 노트가 빠지면 분석으로서 무의미.
- 빈 상태: 브라우즈 모드에서 폴더·노트 전부 없으면 `폴더가 비어 있어요` + `[새 노트]` `[새 폴더]` 인라인 CTA.

### 4.3 사이드바 재구성

```text
┌──────────────┐
│ ◈ 모든 노트 12│  ← 스마트 컬렉션 (쿼리: null)
│ ★ 즐겨찾기  3 │  ← 쿼리: favorites
│ ▦ 갤러리     │  ← 기존
│              │
│ FOLDERS      │  ← 고정 폴더 (FolderDef.pinned)
│ 📁 작업      │  ← 클릭: 브라우즈, DnD 드롭 타깃
│ 📁 일기      │
│              │
│ TAGS         │  ← 기존 태그 칩 (클릭 시 쿼리 모드)
│ …            │
└──────────────┘
```

- 폴더 트리(`buildTree`/`FolderTreeNode`) **삭제**. 현재 위치 하이라이트는 사이드바가 아니라 브레드크럼이 담당.
- 고정 폴더 행: 아이콘(`colorForFolder`) + 이름. 클릭 → `setFolderFilter(path)`. 현재 브라우즈 위치와 일치하면 하이라이트.
- 고정 해제는 행 우클릭 or 설정(§4.6). v1은 설정 토글 + 폴더 카드 콘텍스트의 "사이드바에 고정" 양쪽.

### 4.4 쿼리 모드의 노트 카드

전역 결과에서 각 노트의 위치를 보여준다: 카드 하단(태그 칩 행 아래)에 폴더 칩 — 기존 `MemoDetail` 칩 스타일 축소판(`Folder 12px + 경로`, 폴더색 점). 브라우즈 모드에서는 위치가 자명하므로 미표시.

### 4.5 콘텍스트 메뉴

기존 `CtxMenu` 컴포넌트(Card.tsx) 재사용.

**빈 영역 우클릭**(스크롤러의 빈 곳):
```text
새 노트 (MD)
새 노트 (HTML)
─
새 폴더          ← 낙관적 생성 이식 (§5.3)
```
브라우즈 모드에서는 현재 위치에 생성된다(루트면 루트에). 쿼리 모드에서는 "위치"가 없으므로 빈 영역 우클릭의 새 폴더·새 노트는 **볼트 루트**에 생성하고 완료 즉시 해당 위치로 이동하지 않는다(사용자는 쿼리 결과를 보고 있으므로). 헤더의 `＋ 새 노트`도 동일 규칙.

**폴더 카드 우클릭**:
```text
열기
─
이름 변경        ← 인라인 낙관적 편집 (§5.3)
사이드바에 고정 / 고정 해제
─
삭제…            ← 내용 있으면 확인 대화 (§5.2)
```

**노트 카드 우클릭**: 기존 그대로(즐겨찾기 / 폴더로 이동… / 본문·ID 복사 / 삭제).

### 4.6 설정 — 저장소 섹션

폴더 목록에 고정 토글(핀 아이콘) 추가. 나머지 유지. 트리 삭제로 사이드바 대체 관리면은 여기가 유일한 전체 폴더 목록.

## 5. 노트·폴더 조작

### 5.1 이동 — 드래그 앤 드롭

- **소스**: 노트 카드(그리드/리스트). HTML5 DnD(`draggable` + `dataTransfer`에 note id 배열 — 멀티셀렉트 대비 문자열 배열로 설계하되 v1은 1개).
- **타깃 3종**:
  1. 폴더 카드(메인) — 가장 가까운 목표
  2. 브레드크럼 세그먼트 — 현재 위치의 상위로 옮기기(빈도 높음: "하위 폴더에서 만든 노트를 부모로")
  3. 사이드바 고정 폴더
- **피드백**: 타깃 hover 시 `ring` 하이라이트(유틸리티 `drag-over:ring-*` 불가하므로 state로). 드롭 성공 → 기존 `→ {폴더}` 토스트. 자기 자신의 현재 폴더로 드롭은 no-op.
- 드래그 중 스크롤: 브라우저 기본 auto-scroll에 맡김(가상화 스크롤러에서 HTML5 DnD 기본 동작 확인 후, 불가하면 edge hover 시 `fetchNextPage`/`scrollTo` 보조).
- 폴더→폴더 DnD는 v1 제외(이름 변경으로 커버, §8).

### 5.2 폴더 삭제

내용 노트가 있으면 확인 다이얼로그(간단 `confirm`형 모달, 문구: `"{폴더}"와 노트 {n}개를 휴지통으로 보낼까요?`) → 백엔드 `delete_folder`가 노트 전부 soft-delete 후 폴더 제거. Undo는 휴지통 복원 UI(Future)에 맡김.

### 5.3 낙관적 생성·이름 변경의 메인 영역 이식

사이드바에서 완성한 모델(commit `b5be6ba`)을 그대로:
- 새 폴더 → `create_folder(위치/새 폴더)` 즉시 생성 → 폴더 카드가 이름 선택 상태로 등장 → Enter 확정(변경 시 rename) / Esc 삭제.
- 이름 변경 → 같은 편집 UI, 기존 이름 선택 상태, Enter → `rename_folder`.
- 이식 후 사이드바 헤더의 `+`는 제거(생성 입구는 메인 헤더 `＋` 분할 버튼의 "새 폴더" + 빈 영역 우클릭). 사이드바는 순수 큐레이션 공간이 된다.

## 6. 백엔드 변경

### 6.1 `MemoFilter` immediate 모드 — `crates/oximemo-core/src/memo.rs`

```rust
pub struct MemoFilter {
    // … 기존 필드 …
    /// true = only notes directly in `folder` (no subfolders).
    /// Applies only when `folder` is Some. Default false (recursive).
    pub immediate: bool,
}
```

- `folder_matches(path, folder, immediate)`: immediate면 `dir == folder`만 허용(현재 `starts_with("{folder}/")` 제외). `folder == ""`는 기존대로 loose만 — immediate와 무관하게 동일.
- IPC `list_memos`에 `immediate?: bool` 파라미터 추가(camelCase 바인딩 그대로).
- 브라우저 폴백(`tauri.ts`)은 이미 직속 일치라 `immediate` 파라미터를 무시하도록 수용만(시맨틱 일치).

### 6.2 `rename_folder(from, to)` — core + IPC

core `Vault::rename_folder`:
1. `from` 비었으면 에러. `to` 경로가 이미 존재하는 폴더면 에러(`folder '{to}' already exists`).
2. `to` mkdir. `from` 트리의 노트 파일들을 상대 경로 보존해 이동(`std::fs::rename`, 파일명 불변 — `move_note`와 달리 파일명 재파생 없음. 충돌 시에만 title-slug 재생성).
3. 인덱스/검색: 이동된 각 노트의 `path`로 redb upsert + search upsert(기존 `move_note`의 갱신 로직을 경로 단위로 재사용).
4. `from` 디렉터리 제거, `memos:changed` emit.
5. 하위 폴더의 TEMPLATE.md/html도 함께 이동(파일 이동이므로 자연 해결).
- 트랜잭션성: 실패 시 이미 이동된 파일은 두지 않는다 — 실패한 노트는 원 위치 유지하고 에러 반환(부분 이동 허용, 재시도로 수렴). 재귀 완전성은 이후 `memos:changed` → 재인덱스로 자가 치유(watcher).

### 6.3 `delete_folder(path)` 시맨틱 변경

기존: 내용 노트 있으면 거부. **변경**: 노트 전부 soft-delete(파일을 `.trash/<원래 경로>`로 이동 — 기존 `delete_note`의 휴지통 규칙 재사용) 후 폴더 트리 제거. 프론트 확인 대화는 §5.2. 설정의 기존 "비어 있을 때만 삭제" 제약 제거. **빈 폴더 즉시 삭제는 확인 없이**(기존 동작).

### 6.4 `FolderDef.pinned` + `set_folder_pinned` — `config.rs`

```rust
pub struct FolderDef {
    pub path: String,
    pub view: Option<ViewMode>,
    pub color: Option<String>,
    /// Pinned to the sidebar favorites section.
    #[serde(default, skip_serializing_if = "Option::is_none")]
    pub pinned: Option<bool>,
}
```

- `set_folder_pinned(path, pinned: bool)` IPC — `set_folder_view`와 동일 패턴(엔트리 없으면 생성, pinned=false이고 다른 속성 없으면 엔트리 제거).
- `config_json` 통과(자동 — items 배열 직렬화).
- 브라우저 폴백: `oximemo:folderviews:v1` 옆 `oximemo:folderpins:v1`(string[]).

### 6.5 변경 후 IPC 목록

| 명령 | 변경 |
|---|---|
| `list_memos` | `immediate` 파라미터 추가 |
| `rename_folder` | **신설** |
| `delete_folder` | 내용 → 휴지통 시맨틱으로 교체 |
| `set_folder_pinned` | **신설** |
| `list_folders` | 불변(이미 빈 폴더 포함, 커밋 `1b9827b`) |
| `move_note` | 불변(DnD가 그대로 사용) |

### 6.6 브라우저 폴백 시맨틱

폴백(`tauri.ts`)도 실제 백엔드와 동일 시맨틱을 제공한다:

- `rename_folder(from, to)`: 메모 스토어의 `folder` 프리픽스 치환 + 폴더 집합(`oximemo:folders:v1`) 경로 교체.
- `delete_folder(path)`: 해당 폴더 노트 전부 `deleted_at` 부여(soft-delete) 후 폴더 집합·메모 정리.
- `set_folder_pinned`: `oximemo:folderpins:v1`(string[]) 집합 갱신.

§10 수용 기준 9(폴백 전 시나리오 동일 동작)이 이 절에 의존한다.

## 10. 수용 기준

1. 루트에 폴더 1 + 메모 2 상태에서 메인에 **폴더 카드 1 + 노트 카드 2**가 함께 보인다(폴더가 앞).
2. 폴더 카드 클릭 → 진입, 브레드크럼에 `볼트 › {폴더}`, 노트는 그 폴더 직속만.
3. 브레드크럼 세그먼트 클릭으로 상위 복귀. Escape로도 한 레벨 위.
4. 빈 영역 우클릭 → 새 노트(MD/HTML)·새 폴더. 새 폴더는 이름 선택 상태로 즉시 등장, Esc로 취소 시 사라짐.
5. 노트 카드를 폴더 카드/브레드크럼 세그먼트/사이드바 고정 폴더에 드롭 → 이동 토스트, 목록 갱신.
6. 폴더 우클릭 → 이름 변경(인라인, 즉시 반영), 사이드바 고정(즉시 사이드바 반영), 삭제(내용 있으면 확인 후 노트 휴지통행).
7. 사이드바에 폴더 트리 없음. 스마트 컬렉션·고정 폴더·태그만. "모든 노트"에서 전역 평면 + 카드 폴더 칩.
8. 검색/태그/즐겨찾기/갤러리/빠른 캡처/노트 상세(Context Dock) 전부 기존 동작 회귀 없음.
9. 브라우저 폴백(localStorage)에서 위 1–7 전 시나리오 동일 동작.
10. `cargo test --workspace` + `tsc -b && vite build` green.
