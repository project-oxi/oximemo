# 모바일 리디자인 및 PC 연결 점검 — 2026-10-18

최신 구현과 검증 범위는 아래 **iPhone 중심 재설계 — 읽기와 작성**에 있다.
그 앞의 두 단계는 변경 이력이며, 하단 탐색과 자동 확장 입력란은 최신판에서 대체했다.

PC 앱의 `DESIGN.md`를 기준으로 모바일 목록, 읽기·편집, PC 연결, 설정을
같은 무채색 시스템으로 정리했다. 기존 컴포넌트와 화면 경로를 유지하고
`mobile-shell.css`로 모바일 배치를 적용했다. 작업 전 모바일·동기화 소스는
`target/mobile-redesign-20261018/baseline`에 보존했다.

## 바뀐 화면과 동작

- 메모·PC 연결·설정을 하단 탐색으로 노출했다. 홈에서 연결 상태, 마지막
  동기화, 검색, 전체·초안 필터와 폴더 선택을 바로 확인할 수 있다.
- 목록에 문서 형식, 제목, 본문 요약, 위치와 전송 상태의 계층을 적용했다.
  빈 화면에는 작성 또는 검색·폴더 초기화 동작이 있다.
- 읽기 화면에 제목과 파일 위치를 분리하고 같은 첫 H1의 반복만 미리보기에서
  생략한다. 편집과 읽기는 같은 원문을 사용한다. 본문 입력창이 내용에 따라
  늘어나고 화면이 한 번만 스크롤된다.
- 연결 설정을 저장한 상태와 통신을 확인한 상태를 구분했다. 옛 동기화
  기록이 있어도 새 요청이 실패하면 실패를 표시한다. 통신이 성공해도 문서별
  충돌이나 전송 오류는 남는다.
- 수동 연결은 저장 직후 동기화를 시도한다. PC 주소를 바꾸면서 토큰을
  생략하면 기존 토큰을 다른 PC에 보내지 않고 입력을 요구한다.
- 메모 저장은 기기 초안을 먼저 영속화한 뒤, 등록한 PC가 있으면 전송을
  시도한다. 재시도 요청 ID, 전송 결과가 불확실한 초안의 편집 잠금,
  원문 해시 충돌과 복구 동작은 기존 경로를 유지한다.

## 후속 수정 — 화면 밀도와 아이폰 업데이트

컴포넌트가 크고 목록보다 도구가 먼저 보인다는 사용자 피드백에 따라 배치를
다시 수정했다. 글자 크기만 줄이지 않고 중복 구획, 반복 아이콘 타일과 큰
상태 카드를 제거했다. 동기화는 목록 아래 상태줄로 옮기고 탐색은 아이콘과
이름이 한 줄에 놓이는 형태로 줄였다. 목록의 제목과 요약은 한 줄씩 표시하며
전체 제목은 접근성 이름과 열린 메모에서 계속 확인할 수 있다.

375×812px 브라우저 QA 화면에서 같은 데이터로 측정했다.

| 항목 | 수정 전 | 수정 후 |
| --- | --- | --- |
| 헤더 높이 | 104px | 52px |
| 첫 메모 시작 | 위에서 340px | 위에서 141px |
| 첫 메모 행 높이 | 약 131px | 약 91px |
| 목록 표시 영역 | 445px | 577px |

읽기 화면은 22px 제목 아래에 파일 위치와 모드 전환을 한 행으로 모았다.
본문은 16px, 줄 높이 1.7이며 강제로 띄우던 본문 최소 높이를 없앴다.
연결·설정은 카드 대신 간결한 행으로 정리하고 부가 설명은 펼치기에 넣었다.
44px 터치 영역은 유지하고 검색창·작성 아이콘의 보이는 배경만 줄였다.

프런트엔드 테스트 21개와 production build가 통과했다. 다섯 화면을
320·375·414·768px에서 검사한 20개 조합 모두 가로 넘침이 없으며, 표시 중인
버튼·펼치기·선택 컨트롤과 검색 입력의 높이가 44px 이상이다. 밝은 화면과
어두운 화면, 연결 실패 상태를 다시 확인했다.

기존 개발 서명으로 iPhone용 arm64 앱을 빌드하고 코드 서명을 검증한 다음,
연결된 아이폰의 `com.oximemo.mobile` 앱에 덮어 설치했다. 삭제 후 재설치는
하지 않았다. 설치 전후 기기 캐시의 SHA-256이 동일하고 미전송 초안 1개가
그대로 있음을 확인했다. 실제 아이폰 화면·키보드의 시각 검증이나 PC 연결
설정 변경은 포함하지 않는다.

후속 검증 자료는 `target/mobile-density-20261018/`에 있다.
`density-comparison.json`, `responsive-results.json`, `device-install.json`,
`device-data-verification.json`과 `screenshots/`에 측정 및 설치 결과를 남겼다.
기기 캐시 백업은 같은 폴더의 접근 제한된 `device-backup/`에 보관했다.


## iPhone 중심 재설계 — 읽기와 작성

앞선 밀도 조정은 목록 개수에 치우쳤으며, 아이폰 UX 완료를 입증하지 못했다.
이번 변경은 그 버전을 대체한다. 사용자의 추가 피드백에 따라 **새 메모는
상단 오른쪽에 고정**했다. 하단 작성 바, 세 탭과 상시 동기화 상태줄을 제거했다.
설정에서 PC 연결·휴지통으로 이동하고 명시적인 뒤로 가기로 복귀한다. 검색과
필터는 목록과 함께 스크롤하며 정상 동기화는 화면을 차지하지 않는다.

목록 제목·요약은 기본 약 18/15pt로 두 줄까지 표시하며 보조 정보는 13pt다.
읽기는 제목 28pt, 본문 17pt/1.75를 사용한다. iOS 시스템 본문 크기와 rem을
연결했으며 원문 편집 필드도 최소 16px를 유지한다. 문서 정보는 접어 둔다.
기존 메모는 읽기로 열고 상단 **편집**으로 작성한다. **미리보기**에서 다시
편집할 수 있고 저장은 기기에 먼저 반영한 뒤 열린 메모를 유지한다. 미저장
이탈은 저장·계속 작성·명시적 폐기 중 하나를 선택한다. HTML 원문도 편집을
명시적으로 시작하기 전에는 읽기 전용이다. 본문 입력란에는 큰 포커스 테두리를
그리지 않고 커서를 사용하며 버튼의 키보드 포커스 표시는 유지한다.

새 메모를 열어 둔 채 동기화한 뒤 PC의 문서 ID로 재편집하도록 native 응답에
세션 한정 키 매핑을 추가했다. 제목·본문 일치로 ID를 추측하지 않는다. 매핑은
캐시·문서 형식에 저장하지 않으며, 전송 성공 뒤 manifest 조회만 실패한 경우에도
보존한다. 기존 원문 snapshot, 불확실한 전송의 편집 잠금, guarded writer와
레거시 읽기 정책은 유지한다.

### 긴 글 입력 오류와 수정

실물 검사에서 긴 글을 입력하면 상단 저장·뒤로 가기 버튼이 화면 밖으로 밀리는
문제가 발견됐다. 기본 글자 크기의 시뮬레이터 통과만으로 완료 처리하지 않았다.
UIKit XS를 지정하자 시뮬레이터에서도 같은 실패가 재현됐다. 시스템 크기를 따라
입력 글자가 16px 아래로 내려갈 때 발생하는 iOS focus zoom이 원인이었다.

입력란과 선택 상자에는 최소 16px를 적용하면서 시스템 글자 확대는 유지한다.
읽기 화면은 문서 전체를 스크롤하고, 작성 화면은 고정된 헤더 아래 본문 입력란
내부를 스크롤한다. 끝에 입력하면 마지막 줄을 입력란 안에서 보이게 한다.
문서 바깥 스크롤을 차단하고 시각적 뷰포트 크기를 반영한다. 처음 시도했던
네이티브 UIScrollView 비활성화는 원인을 해결하지 못해 최종 구현에서 제거했다.

XCTest는 소프트웨어 키 존재, 저장 버튼의 hit 가능 여부와 키보드 위 위치를
검사한다. 전체 화면 캡처에 로컬 Vision OCR을 사용해 마지막 입력 줄이 실제로
보이는지도 확인한다. 본문 처음·끝 터치 스크롤, 계속 작성과 명시적 폐기도
확인한다. 스크롤 애니메이션은 최대 6회 안에서 실제 표시를 재확인한다.
